# RESTful Booker – API Testing Project

##  Project Overview

This project demonstrates **REST API testing using Postman** on the RESTful Booker API.

The project covers API functional testing, positive and negative testing, authentication, request/response validation, dynamic test data, data-driven testing, and automated test execution using the **Postman Collection Runner**.

---

##  Tools & Technologies

- **Postman** – API testing and automation
- **JavaScript** – Test scripts and pre-request scripts
- **REST API** – API testing
- **JSON** – Request and response data
- **CSV** – Data-driven testing
- **Excel** – Test cases and execution results
- **Git & GitHub** – Version control and project management

---

## 🔗 API Under Test

**RESTful Booker API**

The API provides booking-related operations such as creating, retrieving, updating, partially updating, and deleting bookings.

## Authentication

Authentication is handled using the token generated by the Create Token API.

The token is stored as a **collection variable** and reused in subsequent authenticated requests.

Example:

```text
Cookie: token={{token}}
```

---

## Postman Variables

The project uses different types of Postman variables.

### Collection Variables

Used for values shared between requests, such as:

```text
token
bookingId
firstName
lastName
totalPrice
depositPaid
checkIn
checkOut
```

### Environment Variables

Used for environment-specific configuration such as the API base URL.

Example:

```text
{{baseUrl}}
{{username}}
{{password}}
```

---

## Pre-request Scripts

Pre-request scripts are used to prepare test data before request execution.

The project generates dynamic values such as:

- Random total price
- Random deposit status
- Check-in date
- Check-out date

Example:

```javascript
const totalPrice = Math.floor(Math.random() * 900) + 100;

const depositPaid = Math.random() < 0.5;

pm.collectionVariables.set("totalPrice", totalPrice);
pm.collectionVariables.set("depositPaid", depositPaid);
```

Dates are also generated dynamically before request execution.

## 📊 Data-Driven Testing

The project uses a CSV file with multiple sets of test data.

Example:

```csv
firstname,lastname
John,Doe
Alice,Smith

```

The values are accessed using:

```javascript
pm.iterationData.get("firstname");
pm.iterationData.get("lastname");
```

This allows the same API test to execute with multiple datasets.

---

## Dynamic Data + Data-Driven Testing

Both approaches are used in the project.

### Data-Driven Data

Values are supplied from the CSV file:

```text
First Name
Last Name
```

### Dynamic Data

Values are generated at runtime:

```text
Total Price
Deposit Status
Check-in Date
Check-out Date
```

This combination helps reduce hard-coded test data and allows the same collection to be executed multiple times with different inputs.

## Automated Assertions

Postman test scripts are used to validate API responses.

Examples of validations include:

- HTTP status code
- Response format
- Booking ID
- Response fields
- Updated values
- Authentication behavior
- Response time

Example:

```javascript
pm.test("Status code is 200", function () {
    pm.response.to.have.status(200);
});

pm.test("Response is JSON", function () {
    pm.response.to.be.json;
});
```

---

## Collection Runner

The Postman Collection Runner is used to execute multiple requests and multiple iterations automatically.

Example execution flow:

```text
Create Token
      ↓
Create Booking
      ↓
PUT Booking
      ↓
PATCH Booking
      ↓
GET Booking
      ↓
DELETE Booking
```

For data-driven execution, the CSV file is supplied to the Collection Runner.

Example:

```text
Iteration 1 → John + Doe
Iteration 2 → Alice + Smith
```
